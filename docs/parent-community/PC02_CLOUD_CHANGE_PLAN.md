## 唯一允许的增量

依据 [002_family_identity.json](../../cloud/schema/002_family_identity.json)：

1. 在已有环境增加一个 `ADMINONLY` 集合 `sc_v2_parent_profiles`，一个唯一索引 `pc02_parent_owner_unique`（`owner_user_id` 升序）。客户端无直接读写权限。
2. 在已有 `sc_v2_app_schema` 增加独立文档 `pc02-family-identity`。先写 version 0 保留本次所有权，验证新集合与索引后才升为 version 2。不修改 `phase04` 文档。
3. 更新已有 `sc-v2-api` 的代码包，保留运行时、内存、超时、已有身份验证、函数所有权和网关配置。新增认证后的 capabilities 与家长资料 GET/PUT；儿童 create/PATCH 支持可选年龄段。
4. 用户主动登录、主动保存后，才产生用户映射、独立家长资料或儿童年龄字段。不得批量回填旧用户、儿童、会话或报告。

`001_metadata.json` 的内容、canonical checksum 和历史索引保持不变。新增年龄字段无需新儿童集合、生日或索引；旧文档缺失字段按 `null` 读取，PATCH 缺省保留原值，显式 `null` 清除。

没有授权时，新功能由 capabilities 关闭；旧服务的 404 也表示不可用。客户端不假装已经保存，不把私有账号名、儿童姓名、UID 或 OpenID 当成公开昵称。

## 回滚与失败处理

当前已保留原 Phase04 部署包，并核对其 SHA256 与历史部署记录一致；PC02 新包在独立的忽略目录构建，通过现有严格包校验。两者均不提交 Git。授权写入前还须重新核实当前函数可恢复版本，若不能确认则停止部署。

发布 ready marker 之前失败时保留 version 0，新功能不可用。若 version 2 更新已发出、随后网络或读回失败，不能假定更新未生效；先只读核实实际 marker 与函数状态，必要时在明确授权范围停用 PC02 marker，再恢复旧函数版本。保留新集合和已有用户记录，不执行删除或反向数据迁移。旧 API 忽略可选年龄字段，旧 Phase04 记录及所有权继续有效。

回滚属于真实云写入，也必须按授权范围执行。不要通过修改 001、开放客户端 ACL 或删除数据来绕过失败。
