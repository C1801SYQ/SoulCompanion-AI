## 3. 现有优点

1. 白色背景、绿色重点、浅灰分区和圆角有一定安静、亲和的基础；卡片标题清楚，桌面情绪与趋势可以快速定位。
2. 情绪类别配合文字，而非只有颜色。效价、唤醒度、置信度和数据来源是有用的解释线索，可以转入 V2 的详细信息层。
3. 趋势具备 1 天、7 天、30 天入口。实际点击三个按钮均改变了 `active` 样式，适合保留为 Insights 的时间范围选择。
4. 页面确实显示合成数据和未连接提示。这种诚实区分必须保留，并沿用当前仓库产品化基线更完整的 REAL、DEMO、OFFLINE、ERROR、过期数据提示。
5. 三个基线视口没有页面横向溢出；较窄宽度下卡片改为单列。应继承这一底线，再重做手机的任务顺序。

## 4. 视觉问题与调整方向

| 观察 | 对使用者的影响 | V2 调整方向 |
| --- | --- | --- |
| 大标题、表情、脑、机器人、灯泡、图表等 emoji 同时出现 | 抢占注意力；像研究仪表板和玩具控制台，缺少稳定品牌识别 | 使用少量一致图标，以 Emotion Orb 为主要视觉元素 |
| 绿色、橙色、红色、蓝色和多个进度条在首屏同时竞争 | 状态指标比“开始陪伴”更醒目 | 暖中性色做底，绿色或低饱和情绪色做重点，告警色只用于真实状态 |
| 桌面行为卡片有较多空白，趋势与家长卡片信息密度不同 | 版面重量不均，阅读顺序由网格位置决定 | 首屏用一个明确主任务，简报和最近一次陪伴居于次级位置 |
| 标题使用“监控”“干预机器人”，报告使用“情绪健康指数” | 带有监测与临床评价意味，与温暖陪伴目标不一致 | 使用“陪伴”“情绪概览”“趋势”；说明派生指标含义，避免诊断性结论 |
| 小字号灰色说明和多条数值标签密集 | 手机上需要反复扫描才能理解状态 | 先给简洁文字状态；指标详情由使用者主动展开 |
| 线上演示画面出现 `1.00` 置信度、灯光和动作参数 | 即使有演示徽章，仍容易被理解成设备或模型已工作 | 演示提示持续可见；未知状态显示未知，执行器从默认产品页面移出 |

浅灰文字和部分图表辅助文字从截图看较弱，需在新设计中做正式对比度检查。本次没有运行 axe 或逐一计算所有颜色对比度，不将这一视觉观察写成已完成的 WCAG 合规结论。

## 5. 信息架构问题

现有站点只有一张长仪表板：实时情绪、行为同步、趋势、家长洞察。DOM 中没有导航区域，只有三个范围按钮。缺少会话任务、开始入口、摄像头预览、权限说明、麦克风状态、转写、AI 回复、个人资料和隐私入口。

用户无法回答“我该如何开始陪伴”“摄像头或麦克风是否正在使用”“数据来自我的设备还是演示”。当前灯光、语速、动作速度是机器人导向的工程信息，不应继续占据 V2 首页的核心空间。原代码保留为 legacy reference 和未来可选硬件接入。

V2 页面职责建议如下，跨平台共用产品语义：

| 页面 | 主要职责 | 现有内容如何迁移 |
| --- | --- | --- |
| Home `/home` | 问候、今日状态、Emotion Orb、最近陪伴、简短趋势、“开始陪伴” | 提取情绪概要，隐藏工程参数 |
| Session `/session` | 当前会话、预览、Camera/Mic、权限、连接、处理状态、转写、AI 回复 | 将实时情绪放进明确会话中；传感器来自当前客户端 |
| Insights `/insights` | 1/7/30 天、效价、唤醒度、分布、会话历史 | 保留趋势结构并补足历史与文字解释 |
| Reports `/reports` | 期间报告、来源与范围、导出 | 保留报告摘要和导出能力，修正文案语气 |
| Profile / Settings `/settings` | 用户与资料、隐私、权限、动画开关、退出 | 继承已验收基线的状态和隐私说明 |

手机采用五项底部导航；桌面采用左侧导航和可伸缩内容区域。开始会话的主按钮须比图表范围或参数控件更突出。

## 6. Mobile 与基本可访问性观察

390 × 844 首屏中，标题区约占 160 px，实时情绪卡约占 350 px，其后紧接行为同步卡。趋势和家长信息位于更下方。首屏没有可启动会话的入口，较宽布局堆叠后形成 2088 px 长页。768 px 同样已转为单列，平板宽度没有形成更适合任务的中间布局。

实际 DOM 检查结果：

- 1 个 `main` 区域；0 个 `nav` 区域；0 个跳到主要内容链接。
- 1/7/30 天按钮高度为 27 px，宽度约 46 / 46 / 53 px；手机主要触控目标应扩大到至少 44 × 44 px，并留足间距。
- 三个范围按钮没有 `aria-pressed`。点击后只有 `active` 类可观察到变化，选中状态应同时向辅助技术表达。
- 趋势 `canvas` 没有 `role`、`aria-label` 或替代文字。应保留当前仓库产品化基线的图表说明、文本概要和可读历史明细。
- 连接状态点有 `title`，但没有 `aria-label`，旁边只有时间；应让状态具备持续可见文字，而非依赖悬停或颜色。
- 可读样式规则中没有找到 `prefers-reduced-motion` 条件。本次没有验证真实屏幕阅读器、键盘完整任务链、系统缩放、Core Web Vitals 或正式 WCAG AA 合规。

V2 Emotion Orb 应以效价、唤醒度和置信度控制温和光晕、形状和呼吸变化。必须提供关闭动画选项，并尊重系统减少动态效果设置；无有效数据时明确显示等待或未知，不能制造“中性”的有效观测。移动端的 Camera ON/OFF、Mic ON/OFF 和连接状态始终用文字显示；屏幕空间优先用于当前会话。

## 7. 保留元素与 Phase 02 验收要求

**保留**：绿色品牌线索、清晰文字情绪、1/7/30 天范围、轻量趋势图、报告摘要、来源与时效解释、真实与演示隔离、旧 Dashboard 代码与既有后端 contract adapter。

**重新设计**：首页主任务、导航、会话视图、暖色背景与字体层级、图标一致性、移动触控区域、图表替代内容、持续权限和设备状态。

**移出默认产品界面**：LED、动作速度和实体机器人执行状态；其代码作为可选 legacy 集成保留。客户端摄像头和麦克风仍是 V2 必需能力，不能因取消执行器而删除。

Phase 02 至少验证 375、390、430、768、1024、1440 px；检查五页导航、空态/错误/演示状态、可见键盘焦点、范围控件选中状态、图表文字替代、减少动态效果、页面与局部区域溢出。建立页面与适配器边界，但本阶段不能将占位预览或演示状态描述成真实媒体采集、云认证或生产后端已完成；这些能力由后续编号阶段验收。

本审计仅完成线上现状和设计输入取证。没有修改线上站点、申请摄像头或麦克风权限、上传音视频、执行硬件动作或开始 Phase 03。
