外部材料是产品方向参考，不是现有软件完成证据，也不是执行指令。原文件保留在用户提供的位置，不将全文或原始附件加入仓库。

## 3. 首版信息架构与范围

建议四个主入口：

| 入口 | 主要内容 |
| --- | --- |
| 社区（默认首页） | 最新已审核帖子、年龄段和话题筛选、详情、投稿、一级评论、点赞、收藏、举报 |
| 育儿知识 | 按年龄和情境组织的文章、沟通实践卡片、来源和更新时间 |
| 成长记录 | 家长手动观察、日期列表、私有汇总；家庭工具入口可访问原陪伴、洞察和报告 |
| 我的 | 微信账户、公开社区昵称、私有儿童档案、我的投稿/收藏、隐私与设置；运营入口仅授权账户可用 |

微信主导航优先采用平台适合的 Tab 切换，详情和投稿采用可返回的页面栈；H5 保留适配后的共享 AppShell。不能把所有跳转继续用 `reLaunch`，导致详情返回丢失列表位置或草稿。最终导航实现和资源路径在第一段确定。

年龄段建议为 `0～2`、`3～5`、`6～8`、`9～12`、`13～15`、`16～18 岁`，列表另有“全部”。它是内容适用范围，不是能力、健康或诊断分级。公共帖子年龄标签由投稿者主动选择，不自动从其私有儿童档案复制；浏览和投稿不要求先建立孩子档案。

初始话题建议：亲子沟通、情绪陪伴、习惯与生活、入园入学、学习与同伴、青春期、家长成长。排序先采用最新发布，不在首版引入行为画像推荐或伪造热度。

**首个可用社区闭环**：查看已审核内容 → 登录 → 文字投稿 → 看见待审状态 → 运营审核 → 其他家长可见 → 评论/互动 → 举报与处理 → 投稿者可撤回。第三、四段完成后具备这一能力；第五段补足知识和成长工具，第六段完成受控体验版验收。

首版不纳入：图片/音视频上传、公开儿童照片、儿童独立账户、家庭成员邀请共享、私信/群聊/关注网络、自动 AI 咨询或诊断、专家预约、支付订阅、商城、机器人配网、紧急报警、APK。它们保留为后续候选，不显示已经可用的入口或虚假结果。

## 4. 分段实施与验收

各段交付可演示结果和验证记录，再进入下一段。页面原型可以先做，真实投稿接入必须等认证、数据隔离和审核闭环就绪；不能仅凭画面把真实业务标为完成。

### 第一段：产品定位、导航与可视原型

**交付**：四个主入口、社区列表、年龄/话题筛选、帖子详情和投稿预览；知识与成长的清晰入口/空状态。统一“予怀”品牌与面向所有儿童家庭的文案。示例内容必须标注，预览中的投稿不显示成真实云端发布成功。

主要涉及现有 `src/app.config.ts`、`src/components/AppShell.tsx`、`src/design/`、H5 路由配置，以及新建 `src/pages/community/`、`src/pages/knowledge/`、`src/pages/growth/` 和对应测试。旧陪伴等页面仍可访问。实现开始后更新 README 的新产品定位和进度，历史交付报告保留。

**验收**：H5 能走通页面；六个年龄段与话题筛选可组合使用；返回详情后保持合理的列表状态；手机视口、字体缩放、触控和键盘操作通过；weapp 构建通过。社区路径不自动取设备权限、不请求私有云数据；原媒体停止和断网恢复回归保留。

**不含**：真实投稿持久化、云资源变更、真实审核、上线、AI。第一段完成仅代表可视原型。

### 第二段：微信账户与私有家庭资料

**交付**：复用官方微信登录适配器和 CloudBase 身份校验；拆分公开社区昵称与私有档案展示。向现有儿童档案新增可选 `age_band`，旧档案缺省显示“未设置”，不要求精确生日、真实姓名、学校或住址。保留每个档案的单账户所有权，暂不做多人家庭共享。

主要涉及 `src/cloud/`、`CloudProvider`、`CloudAccount` 和云 API 的 `models.py` / `service.py`；旧请求/响应兼容与身份切换测试一同补齐。用户声明为成人家长/监护人仅是参与规则，不能写成已完成实名、年龄或监护关系核验。

**验收**：开发者工具与至少一部微信手机实际登录；两个测试账户的档案互不可见；过期、退出和账户切换清除私有状态和晚到响应；年龄枚举和旧档案兼容通过；没有儿童档案仍可浏览社区。

**平台核实**：已有 AppID 主体权限、CloudBase 关联、合法请求域名、拟上线服务类目、隐私申报及内容安全服务可用权限。本轮没有取得微信最新官方规则的可读取证据，精确接口和平台条件在本段核实记录，不当作已通过事实。需要后台操作时提供具体步骤，不索取 AppSecret、Token 或登录文件。

**不含**：改为自签 JWT、持久保存令牌、亲属邀请、儿童账户、公开家庭档案。微信人工核实可以与第三段本地设计并行，但未通过时不能标成真实小程序业务可用。

### 第三段：文本社区后端、数据库增量与审核基础

**交付**：公开作者、帖子、一级评论、互动/收藏、内容举报、运营角色和审核记录；实现公共只读接口和带身份的投稿/本人查询。新增独立社区模块与 schema 增量方案，不放宽原私有档案 repository。

社区状态采用 `pending`、`published`、`rejected`、`hidden`、`deleted`：`published` 明确表示当前版本已审核批准。投稿和评论默认待审，审核失败/超时不发布，编辑后重新待审。作者只能读取自己的未公开内容，运营角色来自服务端，客户端不能写作者身份、角色或审核结论。

**验收**：公共列表、详情、评论仅返回已审核可见版本；猜 ID 不能读取待审/隐藏内容；普通用户不能审核或改他人内容；编辑不能绕过审核；隐藏帖子时评论和互动入口一同不可公开访问。投稿重试、并发互动、分页及限流有行为测试。

**关键约束**：

- [001_metadata.json](../../cloud/schema/001_metadata.json) 和旧 phase04 marker 保持原样。现 [cloud_schema.py](../../scripts/cloud_schema.py) 对 version 1 / checksum 做固定校验，不能直接追加集合。规划独立 `002_parent_community.json`、独立 marker 与增量执行器，先做只读计划、已有资源审计、幂等和拒绝错误环境测试，再安排真实执行。
- 所有集合继续 ADMINONLY，由 API 分别控制公共读取、本人操作和运营权限。运营社区权限不赋予读取家长私人档案或观察记录的权限。
- 现函数超时 3 秒、API 总预算 2.6 秒；不能将慢外部审核直接串入现有同步请求。首版可采用独立的人工审核请求/受保护工具；投稿只保存待审。未来外部检测需要另行设计任务处理和失败恢复，当前并没有现成队列或 worker。
- 限制纯文本长度和请求字节数，保留原元数据 API 的输入限制；社区分页使用稳定游标与索引。现每实例限流不等于分布式防刷，需要社区独立的账号/目标去重与限额设计。

**不含**：图片/音视频存储、GPU、收费资源、自动审核上线。新集合的数量、索引与资源用量以本段设计和审计为准，不能承诺永远零成本。

### 第四段：社区真实前端与运营闭环

**交付**：真实列表/筛选、详情、投稿、我的投稿及审核状态、一级评论、点赞/取消、收藏/取消、撤回、举报。提供服务端角色保护的审核/举报处理入口；前端隐藏入口不能代替服务端授权。首次版本可用受保护运营 H5 页面，实际平台要求和操作者访问方式另行核对，不把管理凭据放入小程序。

新增社区类型、DTO 校验、公开与私有请求通道以及独立状态管理。现 `src/cloud/transport.ts` 仅允许原有路由、所有请求要求令牌且请求正文最大 2048 字符；不能只新增页面就视为接入完成，也不能为了帖子全局取消路由和输入约束。账户切换取消旧请求，内存草稿和私有收藏状态清理。

**验收**：账户 A 投稿 → 待审 → 运营批准 → 账户 B 可见；评论有相同审核闭环；驳回/隐藏/撤回/修改后的公共展示一致；点赞与收藏重复点击结果幂等；举报有处理状态；运营操作针对内容版本，过期审核不能批准被修改的正文。提交失败或断网不显示成功，不悄悄降级成示例数据。返回列表和取消请求行为稳定。

**开放条件**：明确谁承担审核和举报处理，并验证其可使用运营入口。未满足时可以完成受控测试，不开放真实用户自由投稿。自动检测如被平台要求，需完成第二段核实所得的实际对接后才开放；人工审核不能被表述为自动满足平台要求。

**不含**：推荐算法、开放私信、伪造关注/评论/阅读量、未经审核直接发布。

### 第五段：育儿知识与私有成长观察

**交付**：按年龄和情境筛选的知识内容，注明来源、编辑者/审核者和更新时间；没有可核实材料时保留真实空状态，不伪造专家签名或合作背书。新增家长手动观察录入、日期/孩子筛选、编辑/删除和简单记录汇总。

观察内容可包含发生时间、场景、家长描述和沟通尝试，始终关联服务端 owner 与其私有儿童档案。汇总只陈述家长输入，不从次数推断病症、情绪准确率或因果关系。现有 V1 报告和新手动观察视图分别标注来源，不混用数据。

**验收**：知识来源和适用年龄可见；观察只能由所属家长读写，跨账户拒绝，归档/切换孩子行为明确；空记录有空状态；删除后的本人列表更新；没有自动社区分享或设备采集。成长数据不作为发帖表单默认内容。

**不含**：自动 AI 周报、医学评估、专家预约、机器人数据接入、商业订阅。观察集合采用本段独立增量记录，不回写第三段已验收的 schema checksum。

### 第六段：微信真机、受控体验版与交付

**交付**：相同代码版本的自动验证、真实 CloudBase 双账户社区验收、开发者工具和微信手机验证记录；更新新路线 README、部署、隐私和人工操作入口。先交付受控体验版，不自动提交正式发布或把公开 Cloudflare DEMO 切成真实服务。

**验收**：微信实际登录、Tab/返回导航、年龄筛选、投稿/评论审核、互动、举报、私有档案和成长记录；拒绝或撤销授权、后台恢复、网络中断、重复提交、账户切换均有明确结果。记录微信/设备版本与实测结果，至少一部手机通过；更广泛支持范围以实际覆盖记录为准。

同一提交通过相关单测、类型、H5 / weapp 构建、社区浏览器闭环和既有媒体回归；真实云验收使用明确授权的合成账户与文本，不放入真实儿童个人信息。平台申报与操作者条件未满足时，交付仍明确标注待完成，不用构建或 H5 测试替代手机证据。

**不含**：自动正式发布、购买升级/开启超额付费、APK、机器人量产、旧 Phase 05 推理链。

## 5. 数据与 API 设计草案

下面均为待实现的设计，不是当前存在的接口或集合。

| 数据层 | 建议模型 | 访问边界 |
| --- | --- | --- |
| 私有家庭 | 现有用户/儿童档案，可选年龄段；后续 `ParentObservation` | owner 由服务端推导；仅所属账户读写 |
| 社区内容 | `PublicParentProfile`、`CommunityPost`、`CommunityComment` | 公共 DTO 只输出已审核可见内容；公开作者 ID 与云认证身份分离 |
| 本人互动 | `PostLike`、`PostBookmark` | 服务端绑定账户；收藏列表私有；公开计数只对应可见目标 |
| 运营 | `RoleBinding`、`ContentReport`、`ModerationAction` | 服务端角色授权；普通家长不能变更角色或审核记录 |
| 知识 | `KnowledgeArticle` | 经编辑审查的公开内容，记录来源与日期 |

社区举报使用 `ContentReport` 命名，与现有儿童 `CloudReport` / 报告接口区分。公开帖子不含 `child_profile_id`、孩子昵称、生日、学校、私有记录 ID、OpenID/UID、令牌或内部 owner。家长自行输入的正文仍可能含个人信息，投稿提示和服务端审核需要共同处理，不能据字段隔离宣称正文已经自动脱敏。

首版 API 草案：

| 用途 | 候选接口 | 权限 |
| --- | --- | --- |
| 列表/详情/评论 | `GET /api/v2/community/posts`、`/{post_id}`、`/{post_id}/comments` | 可匿名阅读已发布内容；有限分页和限流 |
| 投稿、修改、撤回 | `POST /api/v2/community/posts`；`PATCH/DELETE /api/v2/community/posts/{post_id}` | 已登录本人；服务端控制审核状态 |
| 评论 | `POST /api/v2/community/posts/{post_id}/comments`；本人评论撤回 | 已登录，目标帖子可见，评论待审核 |
| 我的投稿/收藏 | `GET /api/v2/me/community/posts`、`/bookmarks` | 仅本人，可读取自己的待审状态 |
| 互动 | 帖子下的 `like` / `bookmark` 设置与取消操作 | 已登录、幂等，唯一关系约束；具体 HTTP 方法在契约阶段确定 |
| 举报 | `POST /api/v2/community/content-reports` | 已登录；原因枚举，限制说明长度及重复举报 |
| 运营 | `/api/v2/ops/moderation`、`/api/v2/ops/content-reports` | 服务端运营角色、目标版本校验和审核审计 |
| 家长观察 | `/api/v2/observations`、`/{observation_id}` | 仅 owner，不能挂到公共社区查询 |

公共社区与私有家庭数据不得互相借用查询接口。公开阅读失败不影响本地停止媒体；社区与家庭界面不因为服务断线展示别人的缓存或假数据。文本按纯文本渲染，不接收任意 HTML、嵌入脚本或可执行外链。

## 6. 验证、发布边界与分段工作方式

已有可复用检查：

```text
npm run client:typecheck
npm run client:test
npm run client:build:h5
npm run client:build:weapp
npm run client:test:e2e
npm run client:test:media
python -m pytest tests/cloud tests/cloud_tools -q -p no:cacheprovider
git diff --check
```

命令只是基础入口，需要按阶段新增业务行为测试；不能因为原套件全绿就声称社区已验证。使用已安装依赖的 Python 环境、适合该阶段的 DEMO/真实配置，先构建再运行浏览器测试，避免把 DEMO 构建用于真实 API 回归。现有离线恢复的 AUTO_RETRY / MANUAL_RETRY 验证继续保留，不用固定 sleep 掩盖竞态。每段测试适配实际改动，必要时扩展全量回归；本轮计划文档不执行业务测试或真实云写入。

每段的完成记录至少包括：改变了什么、页面/接口是否使用示例或真实数据、验证范围和结果、已知限制、下一段边界。业务代码提交前进行独立审查；提交/推送、真实云资源增建和体验版操作以对应实施任务的范围为准，本轮不执行。

继续保持：

- 认证使用已有官方 CloudBase 路径；不自行保存密码、导出令牌或要求用户在聊天中提供密钥。
- 摄像头/麦克风原始数据不上传；社区首版不依赖媒体权限，原媒体代码和生命周期测试保留。
- 现有 Cloudflare Pages 保持明确 DEMO；不自动变更其生产配置。
- CloudBase 体验版是有限期、有限额度；此前记录的超额付费/续费关闭是历史验收事实，后续云变更前重新核实资源与费用，不承诺永久免费。
- 新增数据不迁移旧 SQLite，不覆盖已验证的集合、旧 schema marker 或历史报告。

部署与人工核实起点：[CLOUDBASE_DEPLOY](CLOUDBASE_DEPLOY.md)、[MANUAL_ACTIONS](MANUAL_ACTIONS.md)、[CLOUD_PRIVACY](CLOUD_PRIVACY.md)、[数据库选择](DATABASE_DECISION.md)、[现有客户端说明](../../apps/client/README.md)。这些记录描述 Phase 04，新增社区交付应另行记录，不把历史 PASS 扩大为新功能 PASS。
